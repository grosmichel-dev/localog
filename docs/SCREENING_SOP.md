# 공개 전 스크리닝 절차 (SCREENING SOP)

문서를 공개(`review_status: screened`)로 바꾸기 전에 반드시 거치는 검토 절차입니다.
CI의 자동 검사는 필요조건일 뿐입니다. 이 절차를 마친 사람의 서명이 충분조건입니다.

## 1. 마스킹 토큰

| 대상 | 토큰 |
|---|---|
| 민간인 성명 | `[REDACTED_성명]` |
| 전화번호·이메일 등 연락처 | `[REDACTED_연락처]` |

토큰을 통일하는 이유: CI의 개인정보 검사가 "마스킹 완료"를 기계적으로 식별해야 하기 때문입니다.

## 2. 민간인 개인정보 마스킹 절차 (본문)

1. 원문과 초안을 나란히 놓고 처음부터 끝까지 읽습니다. AI 초안을 그대로 믿지 않습니다.
2. 사람 이름이 나오면 신분을 확인합니다: 공무원·의원인가, 민간인인가.
3. **민간인의 실명·연락처·주소·사생활 진술**은 토큰으로 치환하거나 문장째 뺍니다.
4. 이름 옆의 소속·직함·동네처럼, 조합하면 누구인지 알 수 있는 정보도 함께 살핍니다.
5. 치환 후 한 번 더 읽어 잔여 흔적(초성 표기, 어설픈 별표 처리 등)을 확인합니다.

### 공무원·의원 예외 (명시)

공무원·의원이 공적 지위에서 한 발언과 그 실명은 마스킹하지 않습니다. 회의 공개 원칙에 따른 공적 기록이기 때문입니다.
단, 공무원이라도 사적 정보(개인 휴대전화 번호 등)가 적혀 있으면 마스킹합니다.

## 3. 원본·이미지 체크리스트

- [ ] PDF·스캔본: OCR을 돌리거나 전 페이지 육안 검사로 민간인 개인정보 여부를 확인했다.
- [ ] 사진: EXIF(촬영 위치·기기 정보)를 제거했다.
- [ ] 원본 속 개인정보를 안전하게 가릴 수 없으면 **그 원본은 커밋하지 않는다.** 대신 `source_url` / `archive_url`만 기록한다.
      (링크는 원천 기관의 책임 범위지만, 우리 저장소에 사본을 두는 순간 우리 책임이 되기 때문)
- [ ] 실제로 검사한 범위를 `screening_scope`에 그대로 적었다.

## 4. 제3자 저작물 체크리스트

행정기관이 직접 만들지 않은 것이 섞여 있으면 그 부분을 뺍니다. 최소한 아래 3가지는 매번 확인합니다.

- [ ] **상업 지도 임베드·캡처** (네이버·카카오·구글 지도 화면)
- [ ] **언론 기사 원문 발췌** (회의자료에 스크랩된 신문·방송 기사)
- [ ] **외부 용역 산출물** (용역업체가 만든 조감도·설계도면·홍보 이미지)
- [ ] (영상 자료라면) 배경음악·삽입 화면

텍스트 전사물(회의록 발언 자체)은 대개 해당 없습니다.

## 4-1. 전사본(자동자막) 추가 확인

유튜브 자동자막으로 만든 전사본(`transcript_source: youtube-auto-caption`)은 아래 3가지를 더 확인합니다.

- [ ] **본문 첫 줄이 고지문인가.** 문구는 고정이며 검증기가 문자열 그대로 비교합니다.
      한 글자라도 다르면 CI가 막습니다. 아래를 그대로 복사해 쓰세요.

```markdown
> 이 문서는 공식 회의록이 아니라 공개 영상·자동자막을 바탕으로 만든 시민 전사본입니다.
> 의미 확인이 필요하면 원문 영상 또는 공식 회의록을 우선합니다.
```

- [ ] **본문 맨 아래에 정정 표가 있는가.** 자막 오인식을 고쳤다면 표에 내역을 남깁니다.

```markdown
## 정정 표

| # | 자막 원문 | 고친 값 | 재확인 |
|---|---|---|---|
| 1 | 대덕구 여산 | 대덕구 예산 | ☐ |
```

      고칠 것이 없었다면 표 대신 `정정 없음` 한 줄을 적습니다.

- [ ] **`screening_scope`에 `transcript`를 포함했는가.** (예: `markdown+transcript`)
      전사 내용을 실제로 검토했다는 서명입니다. 빠지면 CI가 막습니다.

고지문을 두는 이유: 정정 표만 있으면 읽는 사람이 이 문서를 공식 회의록으로 오해할 수 있기 때문입니다.

## 5. 서명 필드 기입법

검토를 마친 사람이 프론트매터에 직접 적습니다. 필드 정의는 `docs/DATA-STANDARD.md` 2-3절과 같습니다.

| 필드 | 적는 값 | 예 |
|---|---|---|
| `review_status` | `draft`로 시작, 검토 완료 시 `screened`로 변경. 공개는 `screened`만 | `screened` |
| `pii_screened_by` | 검토자 핸들 (실명 아님) | `byungki` |
| `screened_at` | 검토를 마친 시각, UTC ISO-8601 | `2026-07-31T02:10:00Z` |
| `screening_scope` | 실제로 검사한 범위 | `markdown+originals+assets` |

- 원본·이미지가 없는 문서는 `screening_scope: markdown`처럼 실제 범위만 적습니다. 검사하지 않은 범위를 적으면 서명 위조입니다.
- 서명이 비었거나 `draft`인 문서는 CI가 병합을 막습니다. 막히는 것이 정상 동작입니다.

## 6. 솔로 구간 추가 규칙

민간인 서술이 든 회의록과 그 원본은 `GOVERNANCE.md` 7절(솔로 운영 잔여 리스크)에 따라,
2번째 검토자를 확보하기 전에는 "기록으로 남긴 추가 마스킹 패스"를 마친 경우에만 공개합니다.
