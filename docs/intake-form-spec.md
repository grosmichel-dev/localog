# 구글폼 사양 (intake-form-spec)

참여자가 자료를 제출하는 구글폼의 질문 구성입니다. 각 질문은 `docs/DATA-STANDARD.md`의 필드에 1:1로 대응합니다.
폼을 만들거나 고칠 때 이 표와 어긋나지 않게 유지하세요.

**출처유형 목록의 정본은 레지스트리(`config/categories/대전시/대덕구.yaml`)입니다. 폼은 사본입니다.**
레지스트리에 분류가 늘거나 줄면 폼의 드롭다운도 따라 고칩니다.

## 1. 질문 목록

폼에 있는 순서 그대로입니다.

| # | 질문(폼에 표시) | 유형 | 필수 | 대응 필드 | 비고 |
|---|---|---|---|---|---|
| 1 | 이메일 | 자동 수집 | 필수 | (대응표 조회용) | 구글이 계정에서 가져옵니다. 저장소에는 들어가지 않습니다 |
| 2 | 올린 곳 | **드롭다운(10개 고정)** | 필수 | `source_type` | 값은 아래 2절 참조. 자유입력 금지 — 표기가 갈리면 자동 분류가 깨집니다 |
| 3 | 게시된 날짜 | 날짜 | 필수 | `date` | 자료가 게시판에 올라온 날 |
| 4 | 담당부서 | 단답 | 필수 | `department` | 원문 표기 그대로 |
| 5 | 제목 | 단답 | 필수 | `title` | 원문 그대로. 게시판 제목에 `날짜 \| 작성자`가 섞여 있으면 `\|` 뒤의 진짜 제목만 |
| 6 | 원문주소(url) | 단답 | 필수 | `source_url` | `http(s)://`로 시작 |
| 7 | 본문 | 장문 | 필수 | (본문) | 원문 복사·붙여넣기. 요약·수정 금지 |
| 8 | 관련근거 | 단답 | 선택 | `관련근거` | 원문에 적힌 문서번호 그대로 (예: `대덕구-청년정책과-2026-0517`) |
| 9 | 신청시작일 | 날짜 | 선택 | `application_starts_at` | 신청·접수가 시작되는 날 |
| 10 | 신청마감일 | 날짜 | 선택 | `application_deadline` | 신청·접수 마감. **채용공고는 비우면 발행이 막힙니다** |
| 11 | 행사시작일 | 날짜 | 선택 | `event_starts_at` | 행사가 열리는 첫날 |
| 12 | 행사종료일 | 날짜 | 선택 | `event_ends_at` | 행사 마지막 날 |
| 13 | 사진첨부 | 파일 업로드 | 선택 | (`assets/` 후보) | 현장 사진 |
| 14 | 사진설명(한줄) | 단답 | 선택 | (사진 캡션) | `DATA-STANDARD` 5절이 요구하는 한 줄 캡션 |
| 15 | 원본파일 | 파일 업로드 | 선택 | (`originals/` 후보) | 원문 PDF·문서 파일 |

### 폼에서 받지 않는 것

| 필드 | 어떻게 채우나 |
|---|---|
| `keywords` | **변환할 때 자동 생성합니다.** 참여자가 직접 뽑으면 사람마다 들쭉날쭉해지고, 어차피 제목·본문에서 나옵니다 |
| `doc_id` | 고시공고·입찰공고는 본문·원문에서 문서번호를 읽어 채웁니다. 나머지는 파일명이 곧 ID입니다 |
| `archive_url` | 운영자가 웹아카이브를 떠서 채웁니다. 실패하면 `archive_status: unavailable` 3종 세트 |
| `posting_starts_at` / `posting_ends_at` | **받지 않습니다.** 게재기간은 신청 마감과 뜻이 달라 오해를 부르고, 주민이 알고 싶은 값도 아닙니다 |
| 필명 | 폼에 문항이 없습니다. **처음 참여하는 분에게는 따로 물어** `private/contributors.yaml`에 등록합니다 |

날짜 질문(9~12)은 **자료에 적힌 것만** 옮깁니다. 해당 없는 칸은 비워 두라고 폼 설명에 명시하세요.

## 1-1. 출처유형 드롭다운 (레지스트리와 글자까지 일치해야 함)

```
구청 공지사항        고시공고            입찰공고
도시계획고시공고      채용공고            행사소식
보도해명            구청장회의(유튜브)    구의회 회의록
예산서
```

띄어쓰기·괄호까지 정본과 같아야 합니다. 정본은 `config/categories/대전시/대덕구.yaml`의 `source_type` 값입니다.
값이 다르면 운영자가 매번 손으로 고쳐야 하고, 한 번 놓치면 검증기가 반려합니다.

## 2. 폼 안내문에 넣을 문구

- "일반 시민(민간인)의 이름·연락처가 보이면 가리고 올려 주세요. (공무원·의원의 공적 발언은 괜찮습니다)"
- "내용을 요약하거나 다듬지 말고 원문 그대로 붙여 주세요."
- "날짜 칸은 자료에 적힌 것만 옮기고, **해당 없는 날짜 칸은 비워 주세요.** 날짜를 추측해 적으면 안 됩니다."
- "이메일은 **누가 몇 건을 보탰는지 세는 용도로만** 받습니다. 사이트에는 여러분이 정한 **필명만** 나오고, 이메일은 공개되지 않습니다. 원하지 않으시면 참여 기록 없이 자료만 보내셔도 됩니다."
- "사진은 **촬영 위치가 함께 저장**되는 경우가 있습니다. 집이나 직장이 드러날 수 있는 사진은 올리지 말아 주세요. (올라온 사진은 공개 전에 위치정보를 지웁니다)"

## 2-1. 파일 업로드 설정

| 문항 | 권장 크기 | 이유 |
|---|---|---|
| 사진첨부 | 작게 (10MB 안팎) | 현장 사진은 클 일이 없고, 위치정보를 지우면 더 작아집니다 |
| 원본파일 | 크게 (100MB 안팎) | 스캔 PDF·회의자료는 수십 MB가 흔합니다 |

원본 파일은 받되, **가릴 수 없는 개인정보가 있으면 커밋하지 않습니다.** 그때는 `source_url`·`archive_url`만
남깁니다(`docs/SCREENING_SOP.md` 3절).

## 3. 폼 설정

- **이메일 수집: 켬.** 참여자별 기여 건수를 세려면 응답을 사람 단위로 묶어야 하는데,
  로그인·본인인증 시스템은 만들지 않기로 했기 때문입니다. 받은 이메일은 **필명 대응표를 만드는 데만** 쓰고,
  그 뒤로는 필명으로 바꿔 다룹니다. 규약은 `docs/CONTRIBUTORS.md`.
- **이메일은 저장소에 절대 들어가지 않습니다.** 대응표는 `private/contributors.yaml`(`.gitignore` 차단)에 두고,
  CI 가 `private/` 아래 파일이 추적되는지 매번 검사합니다.
- 응답 수정 허용은 꺼도 됩니다. 고칠 것이 있으면 재제출이 단순합니다.

## 4. 응답 처리 위치 (중요)

- 응답과 첨부파일은 **저장소 밖 로컬 `inbox/` 폴더**로 내려받아 처리합니다.
- 미검토 원본에는 개인정보가 있을 수 있어, git 저장소 안에 두면 실수 한 번으로 공개될 수 있기 때문입니다.
  `inbox/`는 저장소 밖이라 push가 물리적으로 닿지 않습니다.
- 처음 보는 이메일이면 **참여자에게 쓰고 싶은 필명을 확인하고** `private/contributors.yaml` 에 한 줄 추가합니다.
  이미 등록된 이메일이면 그 필명을 그대로 씁니다. 폼에 적어 낸 필명과 대응표가 다르면 **대응표가 이깁니다**
  (같은 사람이 매번 다르게 적으면 기여도가 갈라지기 때문).
- 문서에 적을 때는 이메일을 **필명으로 바꿔** `pii_screened_by` 에 넣습니다. 이 시점부터 이메일은 어디에도 없습니다.
- 검토·마스킹·서명을 마친 것만 저장소로 옮겨 PR로 올립니다. 흐름은 `docs/COMMIT-FLOW.md`.
- 접수·로그인·본인인증 같은 시스템은 만들지 않습니다. 그런 업무는 행정(구청)의 몫입니다.
