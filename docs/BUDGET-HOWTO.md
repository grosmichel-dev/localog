# 예산서 올리는 법

예산서처럼 **표가 본질인 자료**는 마크다운으로 옮겨 적지 않습니다. **엑셀에서 만든 CSV 를 그대로 올리면**
빌드가 부서별 문서로 나눠서 사이트에 발행합니다.

> 이 문서는 **작업 절차**입니다. 도구가 지켜야 하는 규약은 [BUDGET-CSV-SPEC.md](BUDGET-CSV-SPEC.md) 에 있습니다.

---

## 역할 분담

| 누가 | 무엇을 |
|---|---|
| **형님** | ① 엑셀로 CSV 만들기 ② **"이건 뭘로 나눠줘"** 한 마디 (예: "세출은 부서별로") ③ 개인정보 확인 |
| **작업자(AI)** | 설정 파일(`.meta.yaml`) 작성, PR 올리기 |

**`.meta.yaml` 을 직접 쓰지 않으셔도 됩니다.** CSV 와 나눌 기준만 알려주시면 작업자가 만듭니다.

---

## 1단계 — 엑셀에서 CSV 만들기

### 한 줄에 한 항목씩 (가로로 늘리지 않기)

원본 예산서가 부서마다 열이 옆으로 늘어나는 형태라면, **한 줄에 한 항목**이 되도록 세로로 폅니다.

| 구분 | 부서 | 팀 | 정책사업 | 단위사업 | 세부사업 | 편성목 | 예산액 |
|---|---|---|---|---|---|---|---|
| 일반 | 환경과 | 정책팀 | 대기질개선사업 | 미세먼지저감 | 저감장치보급 | 인건비 | 12,000,000 |
| 일반 | 환경과 | 정책팀 | 대기질개선사업 | 미세먼지저감 | 저감장치보급 | 운영비 | 3,500,000 |

- **첫 줄은 반드시 열 제목**입니다. 비어 있거나 같은 이름이 두 번 나오면 안 됩니다.
- 열 이름은 **자유롭게** 쓰셔도 됩니다. 도구가 열 이름을 미리 정해두지 않습니다.

### 합계행은 원문 그대로 두기

원본에 합계가 있으면 **지우지 말고 그대로** 넣으세요. 사이트가 합계를 다시 계산하지 않습니다.

| 구분 | 부서 | … | 예산액 |
|---|---|---|---|
| 합계 | 환경과 | | 17,500,000 |
| 합계 | | | 51,300,000 |

- `구분` 열에 `합계` 라고 적힌 줄이 합계행입니다.
- **부서가 적힌 합계행** → 그 부서 문서의 합계
- **부서가 빈 합계행** → 전체 합계 (총괄 문서로)

### 저장

엑셀에서 **다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)** 을 고르세요.
일반 `CSV` 로 저장하면 한글이 깨질 수 있습니다.

## 2단계 — 파일 두기

```
content/대전시/대덕구/예산서/2026-세출예산.csv
```

폴더가 없으면 만드세요. 파일 이름은 자유롭지만 `연도-이름` 형태를 권합니다.

---

## 3단계 — 개인정보 (예산서는 신경 쓰지 않으셔도 됩니다)

**예산서는 편성 문서라 지급 대상이 담기지 않습니다.** 누구에게 얼마를 줬는지는 집행내역·
정산서·사업수행상세내역에 있고, 그건 다른 문서입니다. 그래서 예산서를 올릴 때
**이름을 찾아 훑는 작업은 필요 없습니다.**

검사기는 그래도 CSV 전체를 훑습니다. 예산서를 의심해서가 아니라 나중에 **실제로 이름이
들어가는 CSV**(집행내역 등)를 올릴 때를 대비한 것입니다. 깨끗한 데이터에서는 아무 말도 하지 않습니다.

### 검사기가 사람 이름이 아닌 걸 잡았을 때

`docs/pii-exceptions.csv` 에 **그 칸 하나만** 예외로 적습니다.

```csv
파일,행,열,값,사유
content/대전시/대덕구/예산서/2026-세출예산.csv,12,사업명,김포대교보수,다리 이름이며 인명이 아님. 확인 완료.
```

- 5칸(`파일 / 행 / 열 / 값 / 사유`)을 **전부** 채워야 합니다. 하나라도 비면 검사가 막습니다.
- `행` 은 **제목 줄을 뺀** 순서입니다(첫 데이터 줄이 1).
- **열 전체를 검사에서 빼는 방법은 없습니다.** 그 길을 열면 거기로 개인정보가 새기 때문입니다.

## 4단계 — 서명

작업자가 만드는 `.meta.yaml` 에 이 네 줄이 들어갑니다.

```yaml
review_status: screened     # 검토를 마쳤다는 뜻. draft 면 발행되지 않습니다
pii_screened_by: byungki    # 누가 봤는지 (실명 말고 핸들)
screened_at: 2026-01-02T00:00:00Z
screening_scope: markdown+csv
```

이 서명은 **"이 CSV 를 내가 검토했다"**는 뜻입니다. CSV 하나에서 만들어지는 문서 여러 개가
이 서명을 물려받습니다. **도구가 서명을 대신 만들어주지 않습니다** — 서명이 없으면 발행이 멈춥니다.

---

## 5단계 — PR 올리고 병합

브랜치 → PR → 검사 통과 → 병합. 자세한 건 [COMMIT-FLOW.md](COMMIT-FLOW.md) 를 보세요.

병합되면 자동으로:

- 부서별 문서가 만들어져 사이트에 올라갑니다
- 각 문서에 **검색창·열 정렬·현재 화면 합계**가 붙습니다
- **CSV 내려받기** 링크가 생깁니다
- AI 카탈로그(`llms.txt`)에 등록돼 시민이 AI 로 물어볼 수 있습니다

---

## 새 종류의 예산서를 추가할 때

세입예산서처럼 다른 종류를 추가하려면 **CSV 한 개와 "뭘로 나눌지" 한 마디**만 주시면 됩니다.
작업자가 설정 파일을 만들어 붙입니다.

### 코드를 안 고쳐도 되는 경우 / 고쳐야 하는 경우

| 상황 | 필요한 것 |
|---|---|
| **열 하나로 나뉜다** (세출=부서, 세입=회계 등) | 설정 파일만 추가. **코드 변경 없음** |
| **두 열을 합쳐야 나뉜다** (예: 회계+부서) | 코드 변경 필요 (v2) |
| **계산해서 나눠야 한다** (금액 구간별 등) | 코드 변경 필요 (v2) |

단일 열로 의미 있게 나뉘지 않으면 생성기가 **경고를 내고 멈춥니다.** 그때 알려주시면 v2 로 처리합니다.

## 자주 나는 오류

| 메시지 | 뜻 | 해결 |
|---|---|---|
| `짝이 되는 …meta.yaml 가 없습니다` | CSV 만 있고 설정 파일이 없음 | 작업자에게 설정 파일 요청 |
| `review_status 는 정확히 'screened' 여야 합니다` | 검토 서명이 안 끝남 | 개인정보 확인 후 서명 |
| `가리키는 열이 CSV 에 없습니다` | 설정의 열 이름과 CSV 열 제목이 다름 | 열 제목 오타 확인 |
| `같은 슬러그로 겹칩니다` | `환경 과` 와 `환경-과` 처럼 표기만 다른 값이 섞임 | 엑셀에서 표기를 통일 |
| `마스킹되지 않은 개인정보 후보` | 사람 이름으로 보이는 값 발견 | 실명이면 마스킹, 아니면 예외 등록 |
| `헤더가 중복입니다` | 열 제목이 두 번 나옴 | 엑셀에서 열 제목 수정 |

막히는 건 고장이 아니라 **안전장치**입니다.
