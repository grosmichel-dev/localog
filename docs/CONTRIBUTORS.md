# 참여자 신원과 필명 (CONTRIBUTORS)

참여자는 **필명(handle)** 으로만 공개됩니다. 실명도 이메일도 사이트에 나오지 않습니다.

## 1. 왜 이메일을 받나

구글폼은 **이메일 수집을 켭니다.** 누가 몇 건을 보탰는지 세려면 응답을 사람 단위로 묶을 방법이 필요하고,
로그인·본인인증 시스템을 따로 만들지 않기로 했기 때문입니다(그런 건 행정의 몫입니다).

받은 이메일은 **대응표를 만드는 데만** 쓰고, 그 뒤로는 필명으로 바꿔 다룹니다.

## 2. 대응표 위치 — 저장소 밖

```
private/contributors.yaml      ← 실제 대응표. .gitignore 로 차단됨
```

**저장소에 절대 넣지 않습니다.** `content/` 안의 파일은 공개 다운로드로 발행되고,
저장소 어디든 한 번 커밋되면 나중에 지워도 **git 히스토리에 영원히 남습니다.**
CI 가 `private/` 아래 파일이 추적되고 있는지 매번 검사해 막습니다.

형식은 `private/contributors.yaml` 파일 안의 주석에 적혀 있습니다.

## 3. 필명 규칙

- 저장소 전체에서 **유일**해야 합니다. 겹치면 누가 검토했는지 가려지지 않습니다.
- 영문 소문자·숫자·하이픈을 권장합니다. 문서 필드에 그대로 들어가기 때문입니다.
- 실명·이메일 앞부분·소속을 그대로 쓰지 마세요. 그러면 필명의 뜻이 없습니다.
- 참여자가 원하는 이름을 직접 정합니다. 운영자가 임의로 붙이지 않습니다.
- **한 번 정한 필명은 바꾸지 않습니다.** 이미 발행된 문서의 `pii_screened_by` 가 그 값을 가리킵니다.
  부득이 바꾸면 그 사람이 검토한 문서를 전부 찾아 함께 고쳐야 합니다.

## 4. 처리 흐름

```
구글폼 응답 (이메일 포함)
   │
   ▼
저장소 밖 inbox/ 로 내려받음          ← git 이 물리적으로 닿지 않는 곳
   │
   ├─ 처음 보는 이메일이면
   │     참여자에게 쓰고 싶은 필명을 물어보고
   │     private/contributors.yaml 에 한 줄 추가
   │
   ▼
이메일을 필명으로 바꿔 문서에 기입
   pii_screened_by: <handle>
   │
   ▼
검토·마스킹·서명 후 PR              ← 이 시점부터 이메일은 어디에도 없다
```

## 5. 하면 안 되는 것

- `private/contributors.yaml` 을 커밋하거나, 내용을 다른 파일로 옮겨 적는 것
- 문서 프론트매터·본문·커밋 메시지·PR 본문에 이메일을 적는 것
  (`tools/lint-pii.mjs` 가 본문의 이메일을 막지만, 커밋 메시지까지는 못 막습니다)
- 참여자 이메일을 기여도 집계 외의 용도로 쓰는 것
- 필명 없이 이메일 앞부분을 임시로 쓰는 것 — 그대로 굳어집니다

## 6. 참여자에게 알릴 것

폼 안내문에 넣습니다.

> 이메일은 **누가 몇 건을 보탰는지 세는 용도로만** 받습니다.
> 사이트에는 여러분이 정한 **필명만** 나오고, 이메일은 공개되지 않습니다.
> 원하지 않으시면 참여 기록 없이 자료만 보내셔도 됩니다.
