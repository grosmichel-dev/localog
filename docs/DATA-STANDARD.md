# 데이터 표준 (DATA-STANDARD)

localog에 들어가는 모든 문서가 지켜야 하는 형식입니다. 이 표준이 있어야 카탈로그·사이트가 자동으로 만들어집니다.

> **왜 처음에 확정하나**: 필드 정의는 **소급 적용이 안 됩니다.** 문서에 없는 정보는 나중에 스크립트가 만들어낼 수 없습니다.

---

## 1. 폴더 계층 = 지역 정보 (프론트매터에 안 적음)

```
content/
└─ <시도>/
   └─ <시군구>/
      └─ <문서분류>/
         └─ 문서.md
```

실제 예:

```
content/대전시/대덕구/고시공고/2026-05-14-대덕구-청년정책과-2026-0517.md
```

- **지역은 폴더 위치가 유일한 출처**입니다. `region` 같은 필드를 따로 적지 않습니다. (적으면 폴더와 어긋날 수 있음)
- 카탈로그 생성기가 경로에서 시도·시군구를 자동으로 읽습니다.
- 다른 지역이 추가되면 `content/대전시/유성구/…` 처럼 폴더만 늘리면 됩니다.

### 기록 문서 vs 안내 페이지 (검증 대상 구분)

| 구분 | 어떤 파일인가 | 아래 형식 규칙 |
|---|---|---|
| **기록 문서** | `content/<시도>/<시군구>/<분류>/` 안의 파일 (단 `index.md` 제외) | **전부 적용** |
| **안내 페이지** | `index.md`(위치 무관), `content/` 바로 아래 파일(`how-to.md` 등), `content/_generated/` | 면제 (`title`만 있으면 됨) |

- 안내 페이지는 사람이 읽는 설명용이라 날짜·부서·문서번호가 없습니다.
- `index.md`는 폴더마다 하나씩 있으므로 **파일 이름 중복 검사에서도 제외**합니다.

### 문서분류 폴더 ↔ `source_type` 대응 (고정)

| 폴더 이름 | `source_type` 값 |
|---|---|
| `구청공지사항` | `구청 공지사항` |
| `고시공고` | `고시공고` |
| `구청장회의` | `구청장회의(유튜브)` |
| `구의회회의록` | `구의회 회의록` |
| `예산서` | `예산서` |

검증기가 **폴더와 `source_type`이 일치하는지** 검사합니다. (문서를 잘못된 폴더에 넣는 실수 방지)

> 새 분류를 추가할 때는 **enum(§2-1)과 이 폴더 표를 함께** 늘려야 합니다. 하나만 늘리면
> "문서분류 폴더가 표준값이 아닙니다"로 그 폴더 전체가 반려됩니다.

## 2. 프론트매터 (문서 맨 위 `---` 블록)

```markdown
---
title: 2026년 청년 창업 지원사업 공고
date: 2026-05-14
department: 청년정책과
source_type: 고시공고
keywords: [청년, 창업지원, 보조금]
source_url: https://www.daedeok.go.kr/...
archive_url: https://web.archive.org/web/...
doc_id: 대덕구-청년정책과-2026-0517
관련근거: [대덕구-기획예산과-2026-0102]
review_status: screened
pii_screened_by: byungki
screened_at: 2026-07-31T02:10:00Z
screening_scope: markdown+originals+assets
---
```

### 2-1. 모든 문서 필수

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `title` | 문서 제목 | 원문 그대로 |
| `date` | 문서 날짜 | `YYYY-MM-DD` |
| `department` | 담당 부서 | 원문 표기 그대로 |
| `source_type` | 자료 종류 | 아래 enum 5값 중 하나 (폴더와 일치) |
| `keywords` | 핵심 단어 | 배열, **최대 8개** |
| `source_url` | 원문 주소 | `http(s)://` |

**`source_type` 허용값 (이 5개만):**
`구청 공지사항` · `고시공고` · `구청장회의(유튜브)` · `구의회 회의록` · `예산서`

### 2-2. 종류별 추가 필수

`source_type`이 **`고시공고`** 또는 **`구청 공지사항`** 이면:

| 필드 | 왜 필요한가 |
|---|---|
| `doc_id` | 문서 간 근거 연결의 기준 |
| `archive_url` | 행정 게시판 주소는 자주 사라짐 → 웹아카이브 사본 필수 |

`예산서`를 포함한 나머지 종류는 이 조건부 필수 대상이 **아닙니다**. 다만 예산서의 생성 문서는
`doc_id_prefix` 로부터 `doc_id` 를 자동으로 부여받습니다(→ `docs/BUDGET-CSV-SPEC.md`).

### 2-3. 공개 서명 필수 (개인정보 안전장치)

**공개(사이트 게시)되려면 반드시 채워야 합니다.** 안 채우면 CI가 막습니다.

| 필드 | 값 |
|---|---|
| `review_status` | `draft` 또는 `screened` — **공개는 `screened`만** |
| `pii_screened_by` | 검토자 **핸들**(실명 아님, 예: `byungki`) |
| `screened_at` | 검토 완료 시각, **UTC ISO-8601** (예: `2026-07-31T02:10:00Z`) |
| `screening_scope` | 검토 범위 (예: `markdown+originals+assets`) |

> AI가 만든 초안은 `review_status: draft`로 시작합니다. 사람이 원문 대조·마스킹을 마친 뒤에만 `screened`로 바꿉니다.

### 2-4. 선택 (있으면 좋음)

| 필드 | 용도 |
|---|---|
| `관련근거` | 이 문서가 참조하는 다른 문서의 `doc_id` 배열 → 자동 연결 |
| `apply_start` / `apply_end` | 신청 시작·마감일 (알림 기능의 재료) |

## 3. `doc_id` 규칙

- **행정 문서번호를 그대로** 씁니다(완전형: 기관·부서·연도·일련번호).
  예) `대덕구-청년정책과-2026-0517`
- 정규화: 공백 제거, 괄호 제거, 구분자는 하이픈(`-`) 하나로 통일, 앞뒤 공백 제거.
- **문서번호가 없는 자료**(회의록 등)는 `YYYY-MM-DD-<분류>-NN` 형식.
  예) `2026-05-14-구의회회의록-01`
- `doc_id`는 **저장소 전체에서 유일**해야 합니다. (중복 시 CI 차단)

### 근거 연결이 자동으로 되는 원리

`관련근거`에 적은 문자열이 다른 문서의 `doc_id`와 **정확히 100% 일치**할 때만 연결됩니다.
부분 일치·비슷한 값은 연결하지 않습니다. (`2024-1`이 `2024-12`에 잘못 붙는 사고 방지)

아직 등록되지 않은 번호를 적어두면, 나중에 그 문서가 올라오는 순간 자동으로 이어집니다.

## 4. 회의록 안건 앵커

회의록은 안건이 여러 개라, **안건 단위**로 링크를 걸 수 있어야 합니다.

본문에 안건 헤더를 쓸 때 고정 ID를 붙입니다:

```markdown
## 안건 1: 청년 창업 지원사업 예산 심의 {#2026-05-14-구의회회의록-01-a01}
```

- 형식: `{#<doc_id>-a<NN>}` — `NN`은 **두 자리**(`a01`, `a02`, … `a12`)
- 카탈로그는 **안건 1건 = 1행**으로 만들어지고, 각 행이 이 앵커를 가리킵니다.

## 5. 링크·이미지·원본

| 종류 | 쓰는 법 |
|---|---|
| 문서 연결 | `[[다른문서파일명]]` (위키링크) |
| 이미지 | `![[사진.png]]` 또는 `![설명](assets/…)` — **`assets/` 안에만** |
| 원본 첨부 | `[원본 PDF](originals/…)` — 스크리닝 완료본만 |

- 실사 사진은 AI가 읽을 필요 없습니다. **한 줄 캡션**만 답니다. (예: "○○공원 현장 전경, 2026년 5월")
- 사진은 **EXIF(촬영 위치·기기 정보)를 제거**하고 올립니다. → `docs/SCREENING_SOP.md`

## 6. 파일 이름 규칙

**형식**: `YYYY-MM-DD-<식별어>.md`

예) `2026-05-14-대덕구-청년정책과-2026-0517.md`

- 위키링크는 **파일 이름으로** 문서를 찾습니다 → **이름이 겹치면 안 됩니다.** (`공고.md` 같은 흔한 이름 금지)
- **발행한 뒤에는 이름을 바꾸지 않습니다.** 공개된 주소와 남의 AI가 저장한 링크가 깨집니다.
  - 부득이하게 바꿔야 하면 옛 이름을 `aliases`에 남겨 주소를 살립니다.
- 옵시디언 설정에서 **"파일 이름 변경 시 링크 자동 업데이트"를 켜 두세요.**

## 6-1. 표가 본질인 자료: CSV 진본 · 자동 생성 문서

예산서처럼 표가 본질인 자료는 마크다운으로 수기 전사하지 않습니다.

| 파일 | 성격 | 커밋 |
|---|---|---|
| `content/…/예산서/*.csv` | **진본 데이터** | **한다** |
| `content/…/예산서/*.meta.yaml` | 분할 규칙 + 사람 서명 | **한다** |
| `content/…/예산서/YYYY-MM-DD-*.md` | 빌드 산출물 | **하지 않는다** |

- `content/` 안의 `.csv` 는 **진본**이라 커밋합니다. 파생물인 `catalog.csv`·`llms.txt` 와는 성격이 다릅니다.
- 생성 마크다운은 프론트매터 `generated: true` 로 식별하며 빌드 후 삭제됩니다.
  실수로 커밋되면 CI 가 `git ls-files` 로 잡아냅니다.
- **`.gitignore` 에 생성 경로를 넣지 마세요.** Quartz 가 `.gitignore` 를 존중해 페이지를
  통째로 건너뜁니다(`content/_generated/` 와 같은 함정).
- **짝 `.meta.yaml` 이 없는 `.csv` 는 검증에서 차단**됩니다. `content/` 의 비마크다운 파일은
  공개 다운로드로 발행되므로, meta 가 없으면 사람 서명 없이 원본이 공개되는 것과 같습니다.

자세한 규약은 [BUDGET-CSV-SPEC.md](BUDGET-CSV-SPEC.md), 실제 작업 절차는
[BUDGET-HOWTO.md](BUDGET-HOWTO.md) 를 보세요.

## 7. 지키지 않으면 어떻게 되나

푸시하면 GitHub에서 검사가 돌고, 아래에 걸리면 **발행이 막힙니다.**

- 필수 필드 누락 / `source_type`이 enum 밖 / 폴더와 불일치
- `keywords` 9개 이상
- `doc_id` 또는 파일 이름 중복
- 공개인데 `review_status`가 `screened`가 아니거나 서명 필드 누락
- 마스킹 안 된 개인정보 흔적 / EXIF가 남은 사진

막히는 건 고장이 아니라 **안전장치**입니다.
