# 데이터 표준 (DATA-STANDARD)

localog에 들어가는 모든 문서가 지켜야 하는 형식입니다. 이 표준이 있어야 카탈로그·사이트가 자동으로 만들어집니다.

> **왜 처음에 확정하나**: 필드 정의는 **소급 적용이 안 됩니다.** 문서에 없는 정보는 나중에 스크립트가 만들어낼 수 없습니다.

---

## 1. 폴더 계층 = 지역 정보 (프론트매터에 안 적음)

```
content/
└─ <시도>/
   └─ <시군구>/
      └─ <문서분류>/
         └─ 문서.md
```

실제 예:

```
content/대전시/대덕구/고시공고/2026-05-14-대덕구-청년정책과-2026-0517.md
```

- **지역은 폴더 위치가 유일한 출처**입니다. `region` 같은 필드를 따로 적지 않습니다. (적으면 폴더와 어긋날 수 있음)
- 카탈로그 생성기가 경로에서 시도·시군구를 자동으로 읽습니다.
- 다른 지역이 추가되면 `content/대전시/유성구/…` 처럼 폴더만 늘리면 됩니다.

### 기록 문서 vs 안내 페이지 (검증 대상 구분)

| 구분 | 어떤 파일인가 | 아래 형식 규칙 |
|---|---|---|
| **기록 문서** | `content/<시도>/<시군구>/<분류>/` 안의 파일 (단 `index.md` 제외) | **전부 적용** |
| **안내 페이지** | `index.md`(위치 무관), `content/` 바로 아래 파일(`how-to.md` 등), `content/_generated/` | 면제 (`title`만 있으면 됨) |

- 안내 페이지는 사람이 읽는 설명용이라 날짜·부서·문서번호가 없습니다.
- `index.md`는 폴더마다 하나씩 있으므로 **파일 이름 중복 검사에서도 제외**합니다.

### 문서분류 폴더 ↔ `source_type` 대응

**정본은 `config/categories/<시도>/<시군구>.yaml` 입니다.** 어떤 폴더가 허용되는지, 각 분류의
`source_type` 값·문서번호 정책·보존 정책·날짜 필수 여부가 전부 그 파일에 있습니다.
검증기와 카탈로그 생성기도 그 파일을 읽습니다.

새 분류를 추가하려면 그 지자체 yaml에 항목 하나를 넣고, `content/` 아래 같은 이름의 폴더를 만들면 됩니다.
레지스트리에 없는 폴더는 "문서분류 폴더가 표준값이 아닙니다"로 그 폴더 전체가 반려됩니다.

아래 표는 **예시**입니다. (대덕구 레지스트리 일부 — 전체 10개 분류는 `config/categories/대전시/대덕구.yaml` 참조)

| 폴더 이름 (예시) | `source_type` 값 (예시) |
|---|---|
| `구청공지사항` | `공지사항` |
| `고시공고` | `고시공고` |
| `채용공고` | `채용공고` |
| `구의회회의록` | `구의회 회의록` |
| `예산서` | `예산서` |

검증기가 **폴더와 `source_type`이 일치하는지** 검사합니다. (문서를 잘못된 폴더에 넣는 실수 방지)

## 2. 프론트매터 (문서 맨 위 `---` 블록)

```markdown
---
title: 2026년 청년 창업 지원사업 공고
date: 2026-05-14
department: 청년정책과
source_type: 고시공고
keywords: [청년, 창업지원, 보조금]
source_url: https://www.daedeok.go.kr/...
archive_url: https://web.archive.org/web/...
doc_id: 대덕구-청년정책과-2026-0517
posting_starts_at: 2026-05-14
posting_ends_at: 2026-05-28
관련근거: [대덕구-기획예산과-2026-0102]
review_status: screened
pii_screened_by: byungki
screened_at: 2026-07-31T02:10:00Z
screening_scope: markdown+originals+assets
---
```

### 2-1. 모든 문서 필수

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `title` | 문서 제목 | 원문 그대로 |
| `date` | 문서 날짜 | `YYYY-MM-DD` |
| `department` | 담당 부서 | 원문 표기 그대로 |
| `source_type` | 자료 종류 | 레지스트리에 등록된 값 (폴더와 일치) |
| `keywords` | 핵심 단어 | 배열, **최대 8개** |
| `source_url` | 원문 주소 | `http(s)://` |

**`source_type` 허용값**: 그 지자체 레지스트리(`config/categories/<시도>/<시군구>.yaml`)에
등록된 값만 허용됩니다. 대덕구는 현재 10개 분류가 등록돼 있습니다.

### 2-2. 종류별 추가 필수 — 레지스트리의 `doc_id` · `archive` 키

어떤 필드가 더 필요한지는 분류마다 다릅니다. 그 정책은 레지스트리의 두 키가 정합니다.

**`doc_id` 키 — 문서번호 정책**

| 레지스트리 값 | 뜻 |
|---|---|
| `official` | 원천 게시판에 행정 문서번호가 있는 분류. 프론트매터 `doc_id` **필수** (대덕구: 고시공고·입찰공고) |
| `internal` | 게시판에 문서번호가 없는 분류. `doc_id`를 생략하면 **파일명이 곧 ID**가 됩니다 (→ §3 `record_id`) |

공지사항은 원천 게시판에 문서번호가 **없으므로** `internal`입니다. 번호를 지어내 적지 마세요.

**`archive` 키 — 원본 보존 정책** (자세한 규칙은 §5-2)

| 레지스트리 값 | 뜻 |
|---|---|
| `required` | `archive_url` 또는 보존 불가 기록(§5-2 탈출구) 필수 |
| `optional` | 있으면 좋고 없어도 통과 |
| `none` | `archive_url`을 적어도 무시 (유튜브·예산서) |

예산서의 생성 문서는 `doc_id_prefix` 로부터 `doc_id` 를 자동으로 부여받습니다(→ `docs/BUDGET-CSV-SPEC.md`).

### 2-3. 공개 서명 필수 (개인정보 안전장치)

**공개(사이트 게시)되려면 반드시 채워야 합니다.** 안 채우면 CI가 막습니다.

| 필드 | 값 |
|---|---|
| `review_status` | `draft` 또는 `screened` — **공개는 `screened`만** |
| `pii_screened_by` | 검토자 **핸들**(실명 아님, 예: `byungki`) |
| `screened_at` | 검토 완료 시각, **UTC ISO-8601** (예: `2026-07-31T02:10:00Z`) |
| `screening_scope` | 검토 범위 (예: `markdown+originals+assets`) |

> AI가 만든 초안은 `review_status: draft`로 시작합니다. 사람이 원문 대조·마스킹을 마친 뒤에만 `screened`로 바꿉니다.

### 2-4. 선택 (있으면 좋음)

| 필드 | 용도 |
|---|---|
| `관련근거` | 이 문서가 참조하는 다른 문서의 `record_id` 배열 → 자동 연결 |

### 2-5. 날짜 필드 6종 — 의미가 이름에 박혀 있습니다

`date`(게시된 날)는 항상 필수이고, 그 외에 아래 6칸이 있습니다.
**해당 없는 칸은 비워 둡니다.** 값을 지어내 적지 마세요.

| 필드 | 뜻 |
|---|---|
| `application_starts_at` | 신청·접수 시작 |
| `application_deadline` | 신청·접수 마감 — 주민이 가장 알고 싶은 값 |
| `event_starts_at` | 행사 시작 |
| `event_ends_at` | 행사 종료 |
| `posting_starts_at` | 게재 시작 — **지금은 받지 않습니다**(아래 참고) |
| `posting_ends_at` | 게재 종료 — **신청 마감이 아닙니다** |

경우별로 채우는 칸:

| 경우 | 채우는 칸 |
|---|---|
| 단순 공고 (공시송달 등) | `date` 만 |
| 채용공고 | `date` + `application_deadline` (+ `application_starts_at`) |
| 행사 + 신청 접수 | `date` + `event_starts_at` + `event_ends_at` + `application_deadline` |

- 모든 날짜는 `YYYY-MM-DD` 형식입니다.
- **게재기간(`posting_*`)은 2026-08-04부터 받지 않습니다.** 공고가 게시판에 걸려 있는 기간일 뿐
  신청 마감과 뜻이 다르고, 주민이 실제로 알고 싶은 값도 아니기 때문입니다.
  필드 자체는 남겨 두었으므로 적어도 오류는 나지 않습니다. 다시 받기로 하면
  레지스트리의 `dates`에 `posting_*`를 넣으면 됩니다.
- **게재기간을 신청 마감 칸에 적으면 안 됩니다.** `application_deadline`이 비어 있으면
  AI는 신청 마감을 말하지 않습니다. 이름 자체가 방어선입니다.
- 각 쌍에서 시작일이 종료일보다 늦으면 오류입니다. `application_starts_at`만 있고
  `application_deadline`이 없어도 오류입니다.
- 레지스트리의 `required_dates`에 걸린 분류는 그 칸을 비우면 CI가 발행을 막습니다.
  (대덕구: 채용공고 = `application_deadline` 하나뿐)
- `required_dates`가 없는 나머지 분류는 6칸이 전부 비어도 통과합니다.
  원천 게시판에 없는 날짜를 강제하면 기여자가 값을 지어내게 되기 때문입니다.

## 3. `record_id` — 인용·연결의 기준 키

모든 기록 문서는 인용 키 `record_id`를 하나 갖습니다. 사람이 따로 적는 필드가 아니라 이렇게 정해집니다:

```
record_id = doc_id (있으면) 또는 파일명(.md 뺀 것)
```

- `doc_id: official` 분류(대덕구: 고시공고·입찰공고)는 **행정 문서번호를 그대로** `doc_id`에 적습니다.
  예) `대덕구-청년정책과-2026-0517`
  - 정규화: 공백 제거, 괄호 제거, 구분자는 하이픈(`-`) 하나로 통일, 앞뒤 공백 제거.
- `doc_id: internal` 분류는 `doc_id`를 적지 않아도 됩니다. **파일명이 곧 ID**입니다.
  일련번호를 사람이 배정하지 않습니다 — 파일 이름 중복은 CI가 이미 막고 있어서,
  두 사람이 같은 날 같은 게시판을 입력해도 파일명만 다르면 충돌하지 않습니다.
- `doc_id`는 **저장소 전체에서 유일**해야 합니다. (중복 시 CI 차단)
- 카탈로그·근거 연결·안건 앵커가 전부 `record_id`를 씁니다.

### 근거 연결이 자동으로 되는 원리

`관련근거`에 적은 문자열이 다른 문서의 `record_id`와 **정확히 100% 일치**할 때만 연결됩니다.
부분 일치·비슷한 값은 연결하지 않습니다. (`2024-1`이 `2024-12`에 잘못 붙는 사고 방지)

아직 등록되지 않은 번호를 적어두면, 나중에 그 문서가 올라오는 순간 자동으로 이어집니다.

## 4. 회의록 (전사본) 규칙

### 4-1. 안건 앵커

회의록은 안건이 여러 개라, **안건 단위**로 링크를 걸 수 있어야 합니다.

본문에 안건 헤더를 쓸 때 고정 ID를 붙입니다. 파일명이 `2026-05-14-정례회-예산심의.md`라면:

```markdown
## 안건 1: 청년 창업 지원사업 예산 심의 {#2026-05-14-정례회-예산심의-a01}
```

- 형식: `{#<record_id>-a<NN>}` — `NN`은 **두 자리**(`a01`, `a02`, … `a12`).
  그 문서 안에서만 세면 되므로 다른 사람과 번호가 겹칠 걱정이 없습니다.
- **모든 안건 헤딩에 앵커를 직접 적어야 합니다.** 하나라도 빠지면 CI가 막습니다.
- 카탈로그는 **안건 1건 = 1행**으로 만들어지고, 각 행이 이 앵커를 가리킵니다.

### 4-2. 자동자막 전사본: 고지문 + 정정 표

회의록 분류는 프론트매터에 `transcript_source`가 필수입니다.
허용값: `youtube-auto-caption` · `official-minutes` · `manual`.

`transcript_source: youtube-auto-caption`이면 본문에 아래 **둘 다** 있어야 합니다.

**① 본문 첫 줄 고지문** — 문구 고정입니다. 검증기가 첫 줄을 문자열 그대로 비교하므로 **한 글자도 바꾸면 안 됩니다.**

```markdown
> 이 문서는 공식 회의록이 아니라 공개 영상·자동자막을 바탕으로 만든 시민 전사본입니다.
> 의미 확인이 필요하면 원문 영상 또는 공식 회의록을 우선합니다.
```

**② 본문 맨 아래 정정 표** — 자막 오인식을 고친 내역을 남깁니다.

```markdown
## 정정 표

| # | 자막 원문 | 고친 값 | 재확인 |
|---|---|---|---|
| 1 | 대덕구 여산 | 대덕구 예산 | ☐ |
```

- 고칠 게 없으면 표 대신 `정정 없음` 한 줄을 적습니다.
- `screening_scope`에 `transcript`를 포함해야 합니다. (예: `markdown+transcript`)
- 고지문을 강제하는 이유: 정정 표만 있으면 읽는 사람이 이 문서를 공식 회의록으로 오해할 수 있기 때문입니다.

## 5. 링크·이미지·원본

| 종류 | 쓰는 법 |
|---|---|
| 문서 연결 | `[[다른문서파일명]]` (위키링크) |
| 이미지 | `![[사진.png]]` 또는 `![설명](assets/…)` — **`assets/` 안에만** |
| 원본 첨부 | `[원본 PDF](originals/…)` — 스크리닝 완료본만 |

- 실사 사진은 AI가 읽을 필요 없습니다. **한 줄 캡션**만 답니다. (예: "○○공원 현장 전경, 2026년 5월")
- 사진은 **EXIF(촬영 위치·기기 정보)를 제거**하고 올립니다. → `docs/SCREENING_SOP.md`

## 5-1. 제목 정규화

게시판의 제목 열에는 `날짜 | 작성자 | 진짜 제목`처럼 다른 정보가 섞여 있는 경우가 있습니다.
그럴 때는 `|`로 나눈 **마지막 토막만** `title`에 적습니다. `|`가 없으면 전체를 그대로 씁니다.

예) 게시판 표기 `2026-08-03 | 서종우 | 대청호 조류경보 발령 안내`
→ `title: 대청호 조류경보 발령 안내`

담당자 실명이 제목에 섞여 들어오는 것을 막기 위한 규칙입니다.
`title`에 ` | `가 남아 있으면 검증기가 경고를 냅니다.

## 5-2. 원본 보존 정책 (`archive` 키)

행정 게시판 주소는 자주 사라집니다. 레지스트리의 `archive` 값에 따라 요구가 다릅니다.

| `archive` | 요구 |
|---|---|
| `required` | `archive_url`(웹아카이브 사본 주소)이 있어야 함. 불가능했다면 아래 **탈출구 3종 세트** |
| `optional` | 아무것도 강제하지 않음 |
| `none` | `archive_url`을 적어도 무시 (유튜브·예산서) |

**탈출구**: 웨이백 캡처가 실패하거나 상세페이지가 세션 URL이라 보존이 안 되는 게시판이 실제로 있습니다.
그 경우 아래 3개를 **모두** 적으면 통과합니다. "확인했는데 안 되더라"를 기록으로 남기는 장치입니다.

```yaml
archive_status: unavailable
source_checked_at: 2026-08-03   # 확인한 날 (YYYY-MM-DD)
archive_note: 상세페이지가 세션 URL이라 웨이백 캡처 실패
```

## 6. 파일 이름 규칙

**형식**: `YYYY-MM-DD-<식별어>.md`

예) `2026-05-14-대덕구-청년정책과-2026-0517.md`

- 위키링크는 **파일 이름으로** 문서를 찾습니다 → **이름이 겹치면 안 됩니다.** (`공고.md` 같은 흔한 이름 금지)
- **발행한 뒤에는 이름을 바꾸지 않습니다. CI가 막습니다.**
  - 파일명은 `record_id`의 재료입니다(§3). 이름을 바꾸면 `record_id`가 바뀌어
    `관련근거` 연결과 안건 앵커가 **함께 깨집니다.** 공개된 주소와 남의 AI가 저장한 링크도 깨집니다.
  - `aliases`는 옛 **주소**만 살립니다. `record_id`는 살리지 못합니다.
  - 발행 직후 오타를 고치는 등 정말 필요한 경우에만, PR 본문이나 커밋 메시지에
    `ALLOW-RECORD-RENAME`을 적어 의도를 남기고 바꿉니다.
- 옵시디언 설정에서 **"파일 이름 변경 시 링크 자동 업데이트"를 켜 두세요.**

## 6-1. 표가 본질인 자료: CSV 진본 · 자동 생성 문서

예산서처럼 표가 본질인 자료는 마크다운으로 수기 전사하지 않습니다.

| 파일 | 성격 | 커밋 |
|---|---|---|
| `content/…/예산서/*.csv` | **진본 데이터** | **한다** |
| `content/…/예산서/*.meta.yaml` | 분할 규칙 + 사람 서명 | **한다** |
| `content/…/예산서/YYYY-MM-DD-*.md` | 빌드 산출물 | **하지 않는다** |

- `content/` 안의 `.csv` 는 **진본**이라 커밋합니다. 파생물인 `catalog.csv`·`llms.txt` 와는 성격이 다릅니다.
- 생성 마크다운은 프론트매터 `generated: true` 로 식별하며 빌드 후 삭제됩니다.
  실수로 커밋되면 CI 가 `git ls-files` 로 잡아냅니다.
- **`.gitignore` 에 생성 경로를 넣지 마세요.** Quartz 가 `.gitignore` 를 존중해 페이지를
  통째로 건너뜁니다(`content/_generated/` 와 같은 함정).
- **짝 `.meta.yaml` 이 없는 `.csv` 는 검증에서 차단**됩니다. `content/` 의 비마크다운 파일은
  공개 다운로드로 발행되므로, meta 가 없으면 사람 서명 없이 원본이 공개되는 것과 같습니다.

자세한 규약은 [BUDGET-CSV-SPEC.md](BUDGET-CSV-SPEC.md), 실제 작업 절차는
[BUDGET-HOWTO.md](BUDGET-HOWTO.md) 를 보세요.

## 7. 지키지 않으면 어떻게 되나

푸시하면 GitHub에서 검사가 돌고, 아래에 걸리면 **발행이 막힙니다.**

- 필수 필드 누락 / `source_type`이 레지스트리 밖 / 폴더와 불일치
- `keywords` 9개 이상
- `doc_id` 또는 파일 이름 중복
- 레지스트리 `required_dates`에 걸린 날짜 칸이 빈 채 제출 (예: 채용공고에 `application_deadline` 없음)
- `archive: required` 분류인데 `archive_url`도 보존 불가 기록(§5-2)도 없음
- 자동자막 전사본에 고지문·정정 표 없음 / 안건 헤딩에 앵커 없음
- 발행된(`screened`) 기록 문서의 파일 이름 변경
- 공개인데 `review_status`가 `screened`가 아니거나 서명 필드 누락
- 마스킹 안 된 개인정보 흔적 / EXIF가 남은 사진

막히는 건 고장이 아니라 **안전장치**입니다.
