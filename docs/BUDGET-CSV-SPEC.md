# 예산 CSV · meta.yaml 규약

예산서처럼 **표가 본질인 자료**를 다루는 규약입니다. 마크다운으로 수기 전사하지 않고,
**CSV 를 진본으로 커밋**한 뒤 빌드가 분할 마크다운 문서를 자동 생성합니다.

- 이 문서는 **도구·워커용 계약**입니다. 사람이 따라 하는 절차는 [BUDGET-HOWTO.md](BUDGET-HOWTO.md) 를 보세요.
- 관련 도구: `tools/validate-budget-csv.mjs`, `tools/build-budget-pages.mjs`, `tools/lint-pii.mjs`

## 1. 파일 배치

```
content/<시도>/<시군구>/예산서/
├─ 2026-세출예산.csv          진본. 커밋한다.
├─ 2026-세출예산.meta.yaml    분할 규칙 + 공통 프론트매터 + 사람 서명. 커밋한다.
└─ (빌드 중 생성 → 빌드 후 삭제, 커밋하지 않는다)
   2026-01-01-세출예산-환경과.md
   2026-01-01-세출예산-총괄.md
```

- `.csv` 와 `.meta.yaml` 은 **파일명 stem 이 같아야** 짝으로 인식됩니다.
- **짝 `.meta.yaml` 이 없는 `.csv` 는 검증에서 차단**됩니다. `content/` 안의 비마크다운 파일은
  Quartz 가 **공개 다운로드 자산으로 발행**하므로, meta 없는 CSV 는 곧 사람 서명 없이 원본이
  공개되는 것과 같습니다.
- 생성 마크다운은 `.gitignore` 에 넣지 **않습니다**. Quartz 가 `.gitignore` 를 존중해 페이지를
  통째로 건너뛰기 때문입니다. 커밋 방지는 프론트매터 `generated: true` 와 CI 의 `git ls-files`
  검사가 담당합니다.

## 2. CSV 요구사항

| 항목 | 규칙 |
|---|---|
| 인코딩 | UTF-8 (BOM 있어도 됨) |
| 첫 행 | 헤더 필수. **중복 헤더·빈 헤더 금지** |
| 형식 | **롱포맷(tidy)** — 1행 = 최소 집계 단위 1건. 각 행이 계층 경로를 모두 가진다 |
| 인용 | 쉼표·개행·따옴표를 포함한 값은 `"` 로 감싼다. 내부 따옴표는 `""` |
| 열 이름 | **자유**. 도구는 열 이름을 하드코딩하지 않고 meta 가 가리키는 열만 사용한다 |

롱포맷 예:

```csv
구분,부서,팀,정책사업,단위사업,세부사업,편성목,예산액
일반,환경과,정책팀,대기질개선사업,미세먼지저감,저감장치보급,인건비,"12,000,000"
합계,환경과,,,,,,"17,500,000"
합계,,,,,,,"51,300,000"
```

### 합계행 규약

원문 예산서의 합계행은 **그대로 포함**합니다. 사이트는 공식 수치를 다시 만들지 않습니다.

- `total_column` / `total_value` 로 합계행을 식별합니다(위 예에서는 `구분` 열이 `합계`).
- `split_by` 값이 특정 그룹과 같은 합계행 → **그 그룹 문서의 원문 합계행**
- `split_by` 값이 **빈** 합계행 → **전체 합계**(총괄 문서에 별도 표기)
- 합계행은 데이터 그룹에 포함되지 않으며, 화면에서 정렬·필터 대상에서 제외됩니다.

## 3. `*.meta.yaml` 필드

평면 구조만 지원합니다(중첩 매핑 금지). `#` 로 시작하는 줄은 주석입니다.

### 필수

| 필드 | 뜻 |
|---|---|
| `split_by` | **분할 기준이 되는 CSV 열 이름.** 이 값만 바꾸면 분할 방식이 바뀐다 |
| `title_format` | 문서 제목 템플릿. `{열이름}` 자리표시자를 **최소 1개** 포함해야 한다 |
| `doc_id_prefix` | 생성 문서의 `doc_id` 앞부분. 정규형이어야 하고 저장소 안에서 유일해야 한다 |
| `date` | `YYYY-MM-DD` |
| `department` | 자료를 낸 부서 |
| `source_type` | 반드시 `예산서` |
| `source_url` | 원문 URL (`http://` 또는 `https://`) |

### 서명 (필수)

| 필드 | 뜻 |
|---|---|
| `review_status` | **정확히 `screened`.** 값까지 검사한다 — `draft` 면 검증 실패 |
| `pii_screened_by` | 검토자 안정 핸들 (실명 아님) |
| `screened_at` | UTC ISO-8601, `Z` 로 끝남 |
| `screening_scope` | 검토 범위 (예: `markdown+csv`) |

### 선택

| 필드 | 뜻 |
|---|---|
| `summary_group` | 총괄 문서 집계 기준 열 (기본값: `split_by`) |
| `amount_column` | 금액 열. 없으면 첫 수치 열을 자동 사용 |
| `total_column` / `total_value` | 합계행 식별 규약. **함께 쓰거나 함께 생략** |
| `keywords` | 최대 8개 |
| `archive_url` | 아카이브 URL |

예:

```yaml
split_by: 부서
title_format: "2026년 {부서} 세출예산"
summary_group: 부서
amount_column: 예산액
total_column: 구분
total_value: 합계

date: 2026-01-01
department: 기획예산과
source_type: 예산서
keywords: [예산, 세출예산, 2026]
source_url: https://www.daejeon.go.kr/daedeok/...
doc_id_prefix: 대덕구-기획예산과-2026-세출

review_status: screened
pii_screened_by: byungki
screened_at: 2026-01-02T00:00:00Z
screening_scope: markdown+csv
```

## 4. 서명의 의미 (중요)

서명은 **"이 CSV 진본을 누가 언제 검토했다"**는 뜻입니다.

- 생성 문서 N개에 같은 서명이 찍히는 것은 **그 검토의 상속**입니다.
- **생성기는 서명을 만들어내지 않습니다.** meta 에 서명이 없으면 생성이 실패합니다.
- 진본 1개를 검사하면 파생 N개가 함께 안전해지는 구조입니다. N번 검사할 것을 1번으로 줄인 것이지,
  검사를 건너뛴 것이 아닙니다.

### 예산서 자체에는 개인정보가 없다

**예산서는 편성 문서**입니다. `부서 > 정책사업 > 단위사업 > 세부사업 > 편성목 > 금액` 구조이며,
**누구에게 얼마를 줬는지는 담기지 않습니다.** 지급 대상이 나오는 것은 집행내역·정산서·
사업수행상세내역이며, 그건 다른 문서 종류입니다.

따라서 예산 CSV 를 올릴 때 **지급 대상을 찾아 훑는 수작업은 필요하지 않습니다.**

### 그래도 CSV 검사를 켜 두는 이유

`tools/lint-pii.mjs` 는 `content/**/*.csv` **전체**를 검사합니다. 예산서를 의심해서가 아니라,
이 검사기가 **CSV 라는 파일 형식 전반**을 담당하기 때문입니다.

- 깨끗한 데이터에서는 **비용이 0** 입니다(실측: 현실적인 부서명·사업명 픽스처에서 오탐 0건).
- 나중에 집행내역·보조금 교부 목록처럼 **실제로 이름이 들어가는 CSV** 를 올리게 되면
  그때 검사기를 새로 만들 필요 없이 이미 작동합니다.

열 단위로 검사에서 빼는 기능은 **제공하지 않습니다.** 열 하나를 통째로 열어두면 어떤 CSV 든
그 경로로 무검사 공개되기 때문입니다. 오탐은 아래처럼 **셀 단위**로만 예외 처리합니다.

오탐은 `docs/pii-exceptions.csv` 에 **셀 단위**로만 등록합니다.

```csv
파일,행,열,값,사유
content/대전시/대덕구/예산서/2026-세출예산.csv,12,사업명,김포대교보수,다리 이름이며 인명이 아님. 검토자 확인 완료.
```

- 5개 항목(`파일 / 행 / 열 / 값 / 사유`)을 **모두** 적어야 예외로 인정됩니다. 하나라도 비면 검증 실패입니다.
- `행` 은 헤더를 제외한 **데이터 행 번호**(1부터)입니다.
- 등록된 예외는 **실행할 때마다 전부 로그에 출력**됩니다. 무엇을 눈감았는지 항상 보이게 하기 위해서입니다.

## 5. 생성 문서 규약

| 항목 | 규칙 |
|---|---|
| 파일명 | `YYYY-MM-DD-<원본stem>-<split값 슬러그>.md` (원본 stem 앞의 연도는 제거) |
| `doc_id` | `<doc_id_prefix>-<split값 슬러그>` (총괄 문서는 `-총괄`) |
| 프론트매터 | meta 상속 + `generated: true`, `generated_by: build-budget-pages`, `source_csv`, `source_meta`, `budget_has_total_row` |
| 본문 순서 | ① 검색 보강 평문 ② 마크다운 표 ③ 원문 합계 안내 ④ CSV 다운로드 ⑤ 총괄 문서 링크 |

### 본문에 raw HTML 을 넣지 않는다

이 저장소의 `quartz/processors/parse.ts` 는 `remarkRehype({ allowDangerousHtml: true })` 만 쓰고
**`rehype-raw` 가 없습니다.** 그래서 마크다운 본문에 적은 raw `<script>`·`<div>` 는 **DOM 에
생성되지 않습니다.** 화면 컨트롤 마커는 Quartz transformer 가 실제 HAST element 로 주입하며,
대상 판별은 프론트매터 `generated_by: build-budget-pages` 로 합니다.

### CSV 값은 신뢰할 수 없는 입력이다

생성기는 CSV 값을 문맥별로 이스케이프합니다.

- 마크다운 표 셀: `|` → `\|`, 개행 → 공백
- HTML 특수문자: `<` `>` `&` → 엔티티
- 대괄호: `[` `]` → 이스케이프 (→ `[x](javascript:...)` 가 링크로 렌더되지 않음)

> **이 이스케이프를 "지금은 안 뚫리니 불필요하다"는 이유로 제거하지 마세요.**
> 현재 raw HTML 이 렌더되지 않는 것은 `rehype-raw` 가 없어서 생긴 **부수적 성질**이지
> 의도된 방어가 아닙니다. 누군가 `rehype-raw` 를 켜는 순간 공개 시민 페이지의 XSS 가 됩니다.

### 슬러그 충돌은 생성을 중단시킨다

`환경과 ` 와 `환경과` 처럼 표기만 다른 값은 같은 슬러그로 접힙니다. 그대로 두면 **한 부서 문서가
다른 부서 문서를 조용히 덮어써** 데이터가 사라집니다. 검증기와 생성기 모두 충돌을 발견하면
파일을 쓰지 않고 중단하며, 충돌한 원본 값을 출력합니다.

## 6. 합계·필터·찾기가 화면에서 동작하는 방식

| 요구 | 구현 |
|---|---|
| **찾기** (문서 안) | 표 위 검색창 — `static/budget-table.js` |
| **찾기** (사이트 전체) | Quartz 검색 + 표 **바깥**의 평문 블록 |
| **필터** | 검색어로 행 실시간 필터 |
| **합계** | 원문 합계행을 라벨과 함께 그대로 표시 + 필터 시 `현재 화면 합계` 를 **별도로** 표시 |

### 평문 보강 블록에 대한 실측 (2026-07-31)

원래는 표 셀이 검색에 안 잡히는 사례([quartz#1395](https://github.com/jackyzha0/quartz/issues/1395))를 우회하려고 넣었습니다.
**이 저장소에서 실제로 재현되는지 측정한 결과, 재현되지 않습니다.**

빌드 산출물(`public/static/contentIndex.json`)과 배포된 검색 UI 로 확인:

| 검색어 | 어디에 있는 값인가 | 검색 결과 |
|---|---|---|
| `저감장치보급` | 평문 블록 + 표 | 예산 문서 2건 |
| `12,000,000` | **표에만** (수치 열은 평문 블록에서 제외) | 예산 문서 1건 — **찾힘** |
| `일반` | **표에만** (`구분` 열은 평문 블록에서 제외) | 예산 문서 3건 — **찾힘** |

즉 표 셀 내용도 검색됩니다. 다만 인덱스에 들어간 표 텍스트는 구분자 없이 이어 붙습니다
(`구분부서팀정책사업…일반환경과정책팀…12,000,000`).

**그래도 평문 블록은 남깁니다.** 측정 중에 드러난 두 번째 값어치 때문입니다 —
**검색 결과 미리보기**가 평문 블록이 있을 때는 `이 문서에 포함된 항목: 환경과, 대기질개선사업…`
으로 읽히지만, 없으면 이어 붙은 표 텍스트나 엉뚱한 안내 문구가 잡힙니다.

> 이 블록을 지우려면 위 측정을 **다시 해보고** 지우세요. 상류 토크나이저가 바뀌면 표 검색이
> 언제든 깨질 수 있고, 그때 이 블록이 유일한 방어선이 됩니다.

`현재 화면 합계` 는 **지금 보이는 행의 합일 뿐 권위 있는 수치가 아닙니다.** 필터를 걸면 원문
합계와 값이 달라지는 것이 정상이며, 그 차이를 시민이 오해하지 않도록 두 수치에 각각 라벨을 붙입니다.

## 7. 검증 순서 (로컬·CI 동일)

```
stale 정리 → validate-frontmatter → lint-pii → validate-budget-csv(--pairs-out)
          → build-budget-pages(--pairs-in) → build-catalog → Quartz 빌드 → 생성물 정리
```

- **`build-budget-pages` 는 `--pairs-in` 없이는 동작하지 않습니다.** 검증을 통과한
  `(csv, meta)` 쌍만 생성·발행 대상이 됩니다.
- 생성이 **카탈로그보다 먼저** 와야 합니다. 순서가 뒤집히면 예산 문서가 `catalog.csv`·`llms.txt`
  에 실리지 않아 AI 가 자료의 존재를 알지 못합니다.
